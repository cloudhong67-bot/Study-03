로컬 DB(`DATABASE_URL`)에 쌓인 퀴즈 세션·답안·점수로 게임 통계를 집계하고, 통계로 보아 고칠 점을 제안해 줘.
이 명령은 **읽기만** 한다. DB와 파일은 수정하지 말고, 고칠 점은 제안으로만 적어 줘.

## 기간

- 기간 인자: `$ARGUMENTS` (앞뒤 공백은 무시하고 소문자로 비교한다)
  - 비었거나 `all`: 전체 기간
  - `weekly`: 한국 시간 이번 주 월요일 0시부터, `daily`: 오늘 0시부터. 순위표와 같은 기준이므로 시작 시각은 `src/lib/leaderboard-period.ts`의 `periodStart()`로 구한다.
  - 그 밖의 값이면 집계하지 않는다. 사용법(`/quiz-stats weekly`)과 허용값 목록을 보여 준 뒤 멈춘다.
- 세션은 `started_at`, 답안은 `answered_at`, 점수는 `created_at`으로 기간을 자른다.

## DB 접근

- Node로 읽는다: `node --no-warnings --env-file=.env --input-type=module -e '…'`에서 `@prisma/client`의 `PrismaClient`를 쓴다. 집계는 `$queryRaw`(SELECT만)나 `groupBy`·`count`로 하고, 끝나면 `$disconnect()`한다.
- 앱과 같은 계산이 필요하면 TypeScript 모듈을 그대로 불러온다(Node가 타입을 지우고 실행한다): `await import("./src/lib/leaderboard-period.ts")`, `await import("./src/lib/scoring.ts")`, `await import("./src/lib/limits.ts")`. 규칙을 손으로 다시 구현하지 않는다.
- 연결에 실패하면 집계하지 말고, `docker compose up -d db`로 DB를 켜고 `.env`가 있는지 확인하라고 안내한 뒤 멈춘다.
- 출력 첫 줄에 접속한 DB의 호스트·포트·DB 이름을 적는다(비밀번호는 적지 않는다).

## 집계 항목

1. **세션**: 모드별(전체 도전 / 카테고리별(카테고리마다) / 스피드) 시작 수, 완료 수(`completed_at` 있음), 완료율, 점수 등록 수, 등록률
2. **점수** (`scores`, 순위표 단위인 모드+카테고리별): 등록 수, 평균·중앙값·최고 점수, 평균 득점률(score ÷ max_score), 서로 다른 닉네임 수
3. **문제별** (`session_answers`, 문제 id 오름차순): 답안 수, 정답률, 힌트 사용률, 시간 초과 수(스피드), 평균 응답 시간(`elapsed_ms`가 있는 답안만), 오답으로 가장 많이 고른 보기
4. **카테고리별**: 3번을 카테고리로 묶은 정답률·힌트 사용률·평균 응답 시간
5. **난이도별**: `questions.json`의 `difficulty`별 평균 정답률

## 판단 기준

- 답안이 **10개 미만**인 문제는 표본이 적으므로 정답률 판단에서 빼고 `표본 부족`으로 표시한다.
- 표기 난이도와 실제 정답률이 어긋나면 `조정 검토`로 짚는다: easy인데 정답률 60% 미만, hard인데 90% 이상, medium인데 40% 미만 또는 95% 이상.
- 같은 오답을 고른 비율이 정답보다 높으면 `오답 쏠림`으로 짚는다. 정답 오류나 모호한 문장일 수 있으므로 `/quiz-check`로 검증하라고 제안한다.
- 정답률이 같은 난이도의 평균보다 크게 낮거나 높아도, 표본 부족이면 결론을 내리지 않는다.
- 이 DB에는 직접 플레이한 기록만 남는다. E2E 테스트가 만든 세션과 `E2E-` 닉네임 기록은 테스트가 끝나면 지워지고, 단위·통합 테스트는 별도 DB(`trivia_test`)를 쓴다. 통계를 해석할 때 이 점을 함께 적는다.
- 브라우저의 "내 기록"(localStorage `trivia:history`)은 서버에서 읽을 수 없으므로 집계 대상이 아니다.

## 출력 형식

한국어로, 아래 순서대로 출력한다.

1. **요약**: 접속한 DB, 기간(시작 시각을 한국 시간으로 함께), 세션·완료·등록·답안 수
2. **모드별** (표): 모드 · 시작 · 완료 · 완료율 · 등록 · 등록률
3. **순위표별 점수** (표): 순위표 · 등록 수 · 평균 · 중앙값 · 최고 · 평균 득점률 · 닉네임 수
4. **카테고리별** (표): 카테고리 · 답안 수 · 정답률 · 힌트 사용률 · 평균 응답 시간(초)
5. **난이도별** (표): 난이도 · 문제 수 · 답안 수 · 평균 정답률
6. **문제별** (표, id 오름차순): id · 카테고리 · 난이도 · 답안 수 · 정답률 · 힌트 · 시간 초과 · 평균 응답(초) · 비고(`표본 부족`, `조정 검토(→ hard)`, `오답 쏠림(2번 보기)` 등)
7. **제안**: 항목마다 한 줄. 난이도를 바꿀 때는 3·4·3 분포를 깨지 않도록 같은 카테고리 안에서 맞바꾸는 방법을 우선 제안하고, `/quiz-range`·`/quiz-check`로 이어서 점검하라고 안내한다. 제안할 것이 없으면 "제안 없음"이라고 적는다.
