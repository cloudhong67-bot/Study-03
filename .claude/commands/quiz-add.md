`prisma/data/questions.json`에 카테고리 `$0`, 난이도 `$1`인 새 퀴즈 문제를 **1개** 만들어 추가해 줘.
문제는 기존 문제와 같은 형식이어야 하고, CLAUDE.md의 "퀴즈 문제 교차 검증 가이드라인"을 반드시 지켜야 한다.

## 인자 확인

- 카테고리: `$0`, 난이도: `$1` (앞뒤 공백은 무시한다)
- 카테고리는 `prisma/seed.mjs`의 `CATEGORIES`에 있는 `name` 중 하나여야 한다(현재 한국사·과학·지리·일반상식). seed가 모르는 카테고리는 거부하므로, 목록은 추측하지 말고 파일에서 읽는다.
- 난이도는 `easy`, `medium`, `hard` 중 하나여야 한다(소문자).
- 둘 중 하나라도 비었거나 허용값이 아니면 문제를 만들지 않는다. 사용법(`/quiz-add 과학 medium`)과 허용되는 카테고리·난이도 목록을 보여 준 뒤 멈춘다.

## 진행 방법

1. **현황 파악**: Node로 JSON을 읽어 아래 값을 구한다. 줄 단위 grep은 쓰지 않는다.
   - 전체 id 최댓값 (새 id = 최댓값 + 1)
   - 해당 카테고리의 문제 목록(질문·정답), 난이도별 개수, 정답 위치(0–3)별 개수
   - 전체 문제의 정답 위치별 개수, 그리고 id 순서로 마지막 두 문제의 정답 위치
2. **주제 고르기**: 해당 카테고리의 기존 문제와 주제·정답이 겹치지 않게 고른다. 같은 인물·사건·개념을 다른 말로 묻는 것도 중복으로 본다.
3. **난이도 맞추기**: 대상은 14세 이상(PRD)이다. 아래 기준으로 요청한 난이도에 맞는 문제를 만든다.
   - `easy`: 초·중학교 교과서에서 배우거나 대부분이 아는 상식. 오답이 분명히 구별된다.
   - `medium`: 교과 과정에 나오지만 연도·인물·용어를 정확히 기억해야 한다. 오답 중 하나 이상이 그럴듯하다.
   - `hard`: 교과 심화나 덜 알려진 사실. 오답이 모두 같은 범주라서 헷갈린다. 단, 전문가만 아는 지식은 피한다.
4. **교차 검증 가이드라인 적용**:
   - **조건 명시**: 다른 해석이 가능하면 기준을 문장에 넣는다(예: "면적 기준", "2024년 기준").
   - **최상급 표현**: '가장 큰', '최초의' 같은 표현에는 측정 기준(면적·높이·지름 등)과 범위(세계·태양계·남한 등)를 명시한다.
   - **시간과 범위**: 변할 수 있는 정보(인구, 순위, 기록 등)는 시점을 적고, 지리적·분류적 범위를 한정한다. 곧 바뀔 수 있는 정보는 가급적 피한다.
   - **교차 검증**: 정답과 해설에 쓴 사실(연도, 수치, 인물, 장소)은 WebSearch로 **서로 다른 출처 2곳 이상**에서 확인한다. 출처끼리 다르거나 논란이 있으면 주류 학설을 따르고, "~로 알려진", "~로 전해지는"처럼 표현한다. 확인할 수 없으면 그 주제를 버리고 다른 주제를 고른다.
   - **오답 검증**: 오답 3개가 어떤 해석으로도 정답이 될 수 없는지 확인한다.
5. **보기와 정답 위치 정하기**:
   - 보기는 서로 다른 비어 있지 않은 문자열 4개이고, 길이와 형식(인물명끼리, 연도끼리 등)을 비슷하게 맞춘다.
   - 정답 위치는 해당 카테고리에서 가장 적게 쓰인 위치를 우선 고르고, 동률이면 전체에서 적게 쓰인 위치를 고른다. 단, id 순서로 마지막 두 문제와 같은 위치가 되어 같은 위치가 3번 연속되는 일은 피한다.
   - 보기가 수치 순서(연도, 온도, 크기 등)라면 오름차순을 유지하고, 정답 위치는 그 순서에 따른다(CLAUDE.md 규칙).
6. **초안 확인**: 파일을 고치기 전에 아래 "출력 형식"의 1–3을 먼저 보여 주고, 추가할지 사용자에게 확인받는다. 사용자가 수정을 요청하면 반영한 뒤 다시 확인받는다.
7. **추가**: 확인받으면 Edit로 배열의 맨 끝(마지막 `}` 뒤, `]` 앞)에 새 객체를 넣는다.
   - 기존 서식을 그대로 따른다: 2칸 들여쓰기, 필드 순서 `id`, `category`, `difficulty`, `question`, `options`, `answer_index`, `explanation`, `options`는 한 줄 배열, 파일 끝 줄바꿈 유지.
   - `JSON.stringify`로 파일 전체를 다시 쓰지 않는다(`options` 배열이 여러 줄로 풀려 diff가 커진다).
   - 기존 문제의 id는 바꾸지 않는다(seed가 id로 upsert하고, 세션이 참조하는 문제는 DB 트리거가 보호한다).
8. **검증**: Node로 파일을 다시 읽어 `prisma/seed.mjs`의 `validateQuestions`와 같은 규칙을 확인한다. JSON 파싱, id 중복 없음, 알려진 카테고리, `question`·`explanation` 비어 있지 않음, `options` 4개이며 중복 없음, `difficulty` 허용값, `answer_index` 0–3 정수. 실패하면 고치고 다시 검증한다.

## 문체

- `question`은 기존 문제처럼 "~은 무엇일까요?", "~은 누구일까요?", "~은 어디일까요?"로 끝나는 존댓말 의문문으로 쓴다.
- `explanation`은 1–2문장의 "~습니다." 체로 쓴다. 정답의 근거를 밝히고, 가능하면 오답과 헷갈리는 이유나 배경 지식을 하나 덧붙인다.
- 사용자에게 보이는 텍스트는 모두 한국어로 쓴다.

## 3·4·3 규칙 경고

CLAUDE.md "Data and migrations"에 따라 각 카테고리는 easy 3 · medium 4 · hard 3(최대 점수 217)이어야 한다. 문제를 1개 추가하면 이 균형이 깨지고, 카테고리·전체 모드의 최대 점수와 통합 테스트의 기대값(예: 과학 217, 전체 모드 817/821)이 달라진다.
- 초안을 확인받을 때 이 영향을 함께 알린다. 추가 후 해당 카테고리의 난이도 분포를 보여 준다.
- 파일만 수정한다. seed, 마이그레이션, 테스트 코드는 고치지 않는다.

## 출력 형식

한국어로, 아래 순서대로 출력한다.

1. **초안**: 추가할 JSON 객체(코드 블록)
2. **검증 근거**: 확인한 사실마다 한 줄로 쓰고, 출처 2곳 이상의 제목과 URL을 함께 적는다. 가이드라인 항목(조건·최상급 기준·시점·범위)을 어떻게 반영했는지도 적는다.
3. **배치 근거**: 고른 정답 위치와 이유(카테고리·전체 위치별 개수, 연속 여부, 수치 순 여부), 그리고 3·4·3 규칙에 미치는 영향
4. (추가한 뒤) **결과**: 추가한 id, 검증 결과, 추가 후 해당 카테고리의 난이도·정답 위치 분포
5. **다음 단계**: `npm run db:seed`로 로컬 DB에 반영하고, `npm test`로 점수 기대값이 바뀌는 테스트를 확인하라고 안내한다.
